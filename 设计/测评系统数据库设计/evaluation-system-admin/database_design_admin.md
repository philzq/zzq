# 测评后台管理系统数据库设计文档

## 一、系统概述

**测评后台管理系统**是管理员和员工使用的管理系统，用于管理租户、测评账号、财务账单、帮助文档等核心业务数据。

### 1.1 系统定位
- **使用人员**：管理员、员工
- **主要职责**：租户管理、测评账号管理、财务账单管理、帮助文档管理
- **数据权限**：可以查看和管理所有租户的数据

### 1.2 核心功能模块
根据思维导图，系统包含以下核心模块：
1. **账户管理**：创建和管理租户账号，权限角色菜单管理
2. **测评账号管理**：账号基本信息维护、设备绑定、自动分配配置
3. **财务账单管理**：账单创建、支付状态管理、账单明细记录
4. **帮助和公共管理**：帮助文档管理，支持目录层级结构

## 二、数据库设计原则

1. **基于 eladmin 框架**：遵循 eladmin 框架的数据库设计规范
2. **统一命名规范**：使用下划线命名（snake_case）
3. **基础字段统一**：所有表包含创建时间、更新时间、创建人、更新人等基础字段
4. **物理删除**：不支持逻辑删除，使用物理删除
5. **索引优化**：为关键查询字段建立索引，提升查询性能

## 三、表结构设计

### 3.1 租户管理模块

#### 3.1.1 租户表 (bt_tenant)
- **业务说明**：存储租户（企业）基本信息，对应思维导图中的"创建测评平台的客户"
- **创建时机**：管理员创建客户账号时
- **必填字段**：邮箱、公司名称、企业负责人微信号码、负责人电话号码
- **管理员权限**：创建、编辑、禁用/启用租户账号
- **字段说明**：
  - `tenant_name`：租户名称（公司名称）
  - `email`：邮箱（唯一，用于登录）
  - `wechat_id`：企业负责人微信号码
  - `contact_phone`：负责人电话号码
  - `status`：状态（0-禁用，1-启用）
  - `expire_time`：到期时间
- **索引**：
  - `uk_email`：邮箱唯一索引
  - `idx_status`：状态索引
  - `idx_expire_time`：到期时间索引
- **业务逻辑**：
  - 创建的账号首次登录时，通过短信/邮箱验证后，用户自己设定密码
  - 支持用户状态维护，可禁用/解禁

### 3.2 测评账号管理模块

#### 3.2.1 测评账号表 (bt_review_account)
- **业务说明**：存储测评账号信息，用于执行订单任务
- **管理员权限**：创建、编辑、禁用/启用测评账号，配置自动分配
- **字段说明**：
  - `account_name`：账号名称
  - `password`：账号密码（明文存储）
  - `platform_code`：平台编码（关联客户端系统的bt_platform表）
  - `device_id`：设备ID（关联设备表的device_id，一对一关系）
  - `is_auto_assign`：是否自动分配（0-否，1-是）
  - `execution_status`：执行状态（0-空闲，1-执行中）
  - `status`：状态（0-禁用，1-启用）
- **订单类型关联**：通过 `bt_review_account_order_type` 关联表支持一个账号关联多个订单类型
- **设备关联**：通过 `device_id` 字段关联设备表，一个账号对应一个设备（注意设备的均匀分布）
- **索引**：
  - `uk_device_id`：设备ID唯一索引（确保一个设备只能关联一个账号）
  - `idx_platform_code`：平台编码索引
  - `idx_execution_status`：执行状态索引
  - `idx_status`：状态索引
  - `idx_is_auto_assign`：是否自动分配索引
- **业务逻辑**：
  - **自动分配**：定时任务检查待执行的明细订单，根据账号的订单类型匹配、是否自动分配等配置，自动分配执行（队列里的顺序要店铺均分排序）
  - **人工处理**：点击人工处理按钮，进入人工处理状态，可以回填处理，直接修改实际成交订单、付款信息、付款人等
  - **账号执行状态**：记录账号是否正在执行任务中
  - **任务队列**：可以查看账号的任务队列情况（后续可能支持人工调整顺序）

#### 3.2.2 账号订单类型关联表 (bt_review_account_order_type)
- **业务说明**：支持一个账号关联多个订单类型（对应思维导图中的"能力标签"）
- **字段说明**：
  - `review_account_id`：测评账号ID
  - `order_type_id`：订单类型ID（关联客户端系统的bt_order_type表）
  - `sort`：排序
- **索引**：
  - `uk_account_order_type`：账号和订单类型联合唯一索引
  - `idx_review_account_id`：测评账号ID索引
  - `idx_order_type_id`：订单类型ID索引

#### 3.2.3 设备表 (bt_device)
- **业务说明**：存储设备信息，账号与设备是一对一关系
- **管理员权限**：创建、编辑、禁用/启用设备
- **字段说明**：
  - `device_id`：设备ID（设备唯一标识）
  - `device_name`：设备名称
  - `device_type`：设备类型
  - `status`：状态（0-禁用，1-启用）
- **索引**：
  - `uk_device_id`：设备ID唯一索引
  - `idx_status`：状态索引
  - `idx_device_type`：设备类型索引
- **业务逻辑**：注意设备的均匀分布，确保账号分配时设备负载均衡

### 3.3 财务账单管理模块

#### 3.3.1 账单表 (bt_bill)
- **业务说明**：存储账单信息，对应思维导图中的"财务账单"模块
- **管理员权限**：创建账单、查看所有账单、管理支付状态
- **字段说明**：
  - `tenant_id`：租户ID
  - `order_batch_id`：批次订单ID（关联客户端系统的bt_order_batch表）
  - `bill_scene`：账单场景
  - `budget_amount`：预算金额（根据订单类型计算公式得出）
  - `actual_amount`：实际金额（实际支付后填写）
  - `currency`：币种（默认KRW）
  - `payment_status`：支付状态（0-未支付，1-已支付，2-部分支付，3-已退款）
  - `payment_time`：支付时间
  - `payment_method`：支付方式
  - `payment_remark`：支付备注
  - `bill_date`：账单日期
- **索引**：
  - `idx_tenant_id`：租户ID索引
  - `idx_order_batch_id`：批次订单ID索引
  - `idx_bill_scene`：账单场景索引
  - `idx_payment_status`：支付状态索引
  - `idx_bill_date`：账单日期索引
- **业务逻辑**：
  - **提交订单时**：需要依据订单类型支付佣金，先显示预算的金额（根据计算公式得出）
  - **实际支付后**：可以显示实际付款金额
  - **支付状态流转**：线下收到款后，管理台管理员点击状态流转到后面（具体的金额币种等需要录入）

#### 3.3.2 账单明细表 (bt_bill_detail)
- **业务说明**：存储账单明细信息，记录账单的历史变更
- **管理员权限**：查看账单明细
- **字段说明**：
  - `bill_id`：账单ID
  - `item_name`：明细项名称
  - `item_type`：明细项类型
  - `quantity`：数量
  - `unit_price`：单价
  - `budget_amount`：预算金额
  - `actual_amount`：实际金额
  - `currency`：币种
- **索引**：
  - `idx_bill_id`：账单ID索引
- **业务逻辑**：每一个明细订单也有对应的费用详情

### 3.4 帮助和公共管理模块

#### 3.4.1 帮助文档表 (bt_help_document)
- **业务说明**：存储帮助文档信息，支持目录层级结构，对应思维导图中的"使用帮助"
- **管理员权限**：创建、编辑帮助文档和目录
- **字段说明**：
  - `parent_id`：父级ID（用于构建目录层级结构，NULL表示根目录）
  - `is_directory`：是否是目录（0-文档，1-目录）
  - `doc_title`：文档标题/目录名称
  - `doc_content`：文档内容（目录时可为空）
  - `doc_type`：文档类型
  - `doc_category`：文档分类
  - `sort`：排序
  - `status`：状态（0-禁用，1-启用）
  - `view_count`：查看次数
- **索引**：
  - `idx_parent_id`：父级ID索引
  - `idx_is_directory`：是否目录索引
  - `idx_status`：状态索引
  - `idx_doc_type`：文档类型索引
  - `idx_doc_category`：文档分类索引
- **业务逻辑**：
  - 支持目录层级结构，便于管理
  - 可以按平台分类（coupang、naver等）

## 四、关键业务逻辑

### 4.1 租户管理
- **创建租户**：管理员创建租户账号，填写邮箱、公司名称、企业负责人微信号码、负责人电话号码
- **首次登录**：创建的账号首次登录时，通过短信/邮箱验证后，用户自己设定密码
- **状态管理**：支持禁用/启用租户账号

### 4.2 测评账号管理
- **账号创建**：管理员创建测评账号，配置平台、设备、订单类型等
- **自动分配**：
  - 定时任务检查待执行的明细订单
  - 根据账号的订单类型匹配、是否自动分配等配置，自动分配执行
  - 队列里的顺序要店铺均分排序
- **人工处理**：
  - 点击人工处理按钮，进入人工处理状态
  - 可以回填处理，直接修改实际成交订单、付款信息、付款人等
- **设备绑定**：账号与设备是一对一关系，注意设备的均匀分布

### 4.3 财务账单管理
- **账单创建**：提交订单（汇总）时，需要依据订单类型支付佣金
- **预算金额**：先显示预算的金额（根据计算公式得出）
- **实际支付**：实际支付后可以显示实际付款金额
- **支付状态流转**：线下收到款后，管理台管理员点击状态流转到后面（具体的金额币种等需要录入）

### 4.4 订单分配流程
1. **待执行需求**：订单创建后进入待执行状态
2. **自动分配**：
   - 程序自动分配：根据账号的订单类型匹配、是否自动分配等配置
   - 定时任务检查待执行的明细订单，自动分配执行
3. **人工处理**：
   - 选择明细订单，点自动处理，选执行账号，确认，就分配好
   - 或点击人工处理按钮，进入人工处理状态

## 六、表关系说明

### 6.1 核心表关系

```
bt_tenant (租户表)
    ↓ (1:N)
bt_bill (账单表)
    ↓ (1:N)
bt_bill_detail (账单明细表)

bt_review_account (测评账号表)
    ↓ (1:1)
bt_device (设备表)
    ↓ (N:M)
bt_review_account_order_type (账号订单类型关联表)
    ↓ (N:1)
bt_order_type (订单类型表) - 位于客户端系统
```

### 6.2 与客户端系统的关联

- `bt_bill.order_batch_id` → 关联客户端系统的 `bt_order_batch.id`（批次订单）
- `bt_review_account_order_type.order_type_id` → 关联客户端系统的 `bt_order_type.id`（订单类型）
- `bt_review_account.platform_code` → 关联客户端系统的 `bt_platform.platform_code`（平台）

## 八、索引说明

所有关键查询字段都已建立索引，包括：
- 外键字段索引（tenant_id、order_batch_id等）
- 状态字段索引（status、payment_status等）
- 日期字段索引（expire_time、bill_date等）
- 业务查询字段索引（platform_code、execution_status等）

索引设计遵循以下原则：
- 为经常用于WHERE条件的字段建立索引
- 为外键关联字段建立索引
- 为排序和分组字段建立索引
- 避免过度索引，平衡查询性能和写入性能
