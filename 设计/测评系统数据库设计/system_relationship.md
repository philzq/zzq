# 测评后台管理系统与测评系统数据关系说明

## 一、系统概述

本系统包含两个独立的子系统：

1. **测评后台管理系统**（admin_system）
   - 使用人员：管理员、员工
   - 数据库表前缀：`bt_`
   - 功能：管理租户、平台、测评账号、财务账单、帮助文档等

2. **测评系统**（client_system）
   - 使用人员：客户（企业）
   - 数据库表前缀：`client_`
   - 功能：创建订单、填写订单、查询订单、管理店铺和产品、查看财务账单等

## 二、数据共享策略

### 2.1 共享数据表

以下数据表在两个系统中共享，通过数据同步机制保持一致：

#### 2.1.1 平台数据（platform）
- **后台系统表**：`bt_platform`
- **测评系统**：通过关联 `platform_id` 引用，不单独存储
- **同步机制**：后台系统创建/修改平台后，测评系统通过接口或视图获取

### 2.2 独立数据表

以下数据表在两个系统中独立存储，但需要数据同步：

#### 2.2.1 租户/客户数据（tenant/customer）

**后台系统**：`bt_tenant`
- 管理员创建租户账号
- 管理租户状态（禁用/启用）
- 查看所有租户信息

**测评系统**：`client_customer`
- 客户查看和修改自己的账号信息
- 首次登录设置密码

**同步机制**：
- 后台系统创建租户后，同步到测评系统（作为客户）
- 客户在测评系统修改信息后，同步到后台系统
- 后台系统禁用/启用租户，同步到测评系统

#### 2.2.2 账单数据（bill）

**后台系统**：`bt_bill`、`bt_bill_detail`
- 查看所有租户的账单
- 支付状态管理
- 通过订单ID关联测评系统的订单

**测评系统**：`client_bill`、`client_bill_detail`
- 客户查看自己的账单
- 客户支付佣金

**同步机制**：
- 客户提交订单时，在测评系统生成账单，同步到后台系统
- 客户支付后，支付信息同步到后台系统
- 后台系统更新支付状态后，同步到测评系统

### 2.3 后台系统独有数据表

以下数据表仅在后台系统中存在：

- `bt_tenant` - 租户表
- `bt_platform` - 平台表
- `bt_review_account` - 测评账号表
- `bt_review_account_order_type` - 账号订单类型关联表
- `bt_account_device` - 账号设备绑定表
- `bt_bill` - 账单表
- `bt_bill_detail` - 账单明细表
- `bt_help_document` - 帮助文档表（可同步到测评系统）

## 三、数据同步方案

### 3.1 实时同步

对于关键数据，采用实时同步：

1. **订单创建**：客户创建订单后，立即同步到后台系统
2. **订单状态更新**：后台系统更新订单状态后，立即同步到测评系统
3. **支付状态**：客户支付后，立即同步到后台系统

### 3.2 定时同步

对于非关键数据，采用定时同步：

1. **店铺数据**：每小时同步一次
2. **产品数据**：每小时同步一次
3. **客户信息**：每天同步一次

### 3.3 同步实现方式

#### 方案一：消息队列（推荐）
- 使用 RabbitMQ、Kafka 等消息队列
- 数据变更时发送消息
- 消费端接收消息并同步数据

#### 方案二：数据库触发器
- 在数据库层面设置触发器
- 数据变更时触发同步逻辑
- 适合简单的同步场景

#### 方案三：接口调用
- 通过 REST API 或 RPC 调用
- 数据变更时调用同步接口
- 适合实时性要求高的场景

#### 方案四：共享数据库视图
- 对于只读数据，使用数据库视图
- 两个系统访问同一个视图
- 适合配置类数据

## 四、数据一致性保证

### 4.1 主数据源

- **客户数据**：后台系统为主数据源
- **店铺数据**：测评系统为主数据源（创建和修改）
- **产品数据**：测评系统为主数据源（创建和修改）
- **订单数据**：测评系统为主数据源（创建），后台系统为主数据源（状态更新）
- **账单数据**：测评系统为主数据源（创建），后台系统为主数据源（支付状态）

### 4.2 冲突处理

1. **客户信息冲突**：以后台系统为准
2. **店铺/产品信息冲突**：以测评系统为准（客户自己的数据）
3. **订单状态冲突**：以后台系统为准（管理员分配和状态更新）

### 4.3 数据校验

1. **唯一性校验**：产品ID、订单号等在两个系统中保持唯一
2. **外键校验**：确保关联数据的完整性
3. **数据完整性校验**：同步前后校验数据完整性

## 五、权限隔离

### 5.1 数据访问权限

- **后台系统**：可以访问所有数据
- **测评系统**：只能访问自己客户的数据

### 5.2 数据操作权限

- **后台系统**：
  - 创建、编辑、删除客户
  - 查看所有店铺和产品
  - 分配订单、更新订单状态
  - 管理测评账号

- **测评系统**：
  - 查看和修改自己的账号信息
  - 管理自己的店铺和产品
  - 创建和填写订单
  - 查看自己的账单

## 六、实施建议

### 6.1 开发阶段

1. 先开发后台管理系统，建立基础数据
2. 再开发测评系统，实现数据同步
3. 测试数据同步的准确性和实时性

### 6.2 部署阶段

1. 两个系统可以部署在同一数据库，使用不同表前缀
2. 也可以部署在不同数据库，通过接口或消息队列同步
3. 建议使用消息队列实现数据同步，保证数据一致性

### 6.3 运维阶段

1. 监控数据同步状态
2. 定期校验数据一致性
3. 建立数据同步异常处理机制

## 七、表关系映射

### 7.1 租户/客户数据映射

```
bt_tenant.id ←→ client_customer.id (通过 tenant_id/customer_id 关联)
```

### 7.2 账单数据映射

```
bt_bill.id ←→ client_bill.id (通过ID关联)
bt_bill.order_batch_id ←→ client_order_batch.id (关联测评系统的订单)
bt_bill_detail.order_detail_id ←→ client_order_detail.id (关联测评系统的订单)
```


## 八、注意事项

1. **数据同步延迟**：需要考虑网络延迟和系统负载，合理设置同步策略
2. **数据冲突**：明确主数据源，避免数据冲突
3. **性能优化**：大量数据同步时，考虑批量同步和异步处理
4. **异常处理**：建立完善的异常处理和回滚机制
5. **日志记录**：记录所有数据同步操作，便于问题排查
