# 测评系统详细设计文档

## 一、系统概述

### 1.1 项目背景

测评填单系统是一个基于 eladmin 框架的订单管理和自动化执行系统，主要用于管理测评订单、账号分配、自动化业务执行等核心业务流程。系统采用前后端分离架构，包含两个独立的子系统：测评后台管理系统和测评系统。

### 1.2 系统架构

系统采用双系统架构设计：

1. **测评后台管理系统（evaluation-system-admin）**
   - 使用人员：管理员、员工
   - 主要功能：租户管理、测评账号管理、财务账单管理、帮助文档管理
   - 数据库：MySQL（表前缀：`bt_`）

2. **测评系统（evaluation-system-client）**
   - 使用人员：客户（企业）
   - 主要功能：平台管理、订单类型管理、店铺管理、产品管理、订单创建和填写、订单查询
   - 数据库：MySQL（表前缀：`bt_`）

3. **自动化系统（hubstudio_api_auto）**
   - 功能：自动化业务执行（测评、点击、加购）
   - 与后台系统交互，执行订单任务

### 1.3 技术栈

- **后端框架**：基于 eladmin 框架
- **数据库**：MySQL 5.7+
- **字符集**：utf8mb4
- **缓存**：Redis（用于账号能力标签缓存）
- **消息队列**：RabbitMQ/Kafka（推荐用于数据同步）

## 二、数据库设计

### 2.1 后台管理系统数据库设计

#### 2.1.1 租户管理模块

**租户表（bt_tenant）**
- 存储租户（企业）基本信息
- 核心字段：
  - `tenant_name`：租户名称（公司名称）
  - `email`：邮箱（唯一，用于登录）
  - `wechat_id`：企业负责人微信号码
  - `contact_phone`：负责人电话号码
  - `status`：状态（0-禁用，1-启用）
  - `expire_time`：到期时间
- 索引：`uk_email`（邮箱唯一索引）、`idx_status`、`idx_expire_time`

#### 2.1.2 测评账号管理模块

**测评账号表（bt_review_account）**
- 存储测评账号信息，用于执行订单任务
- 核心字段：
  - `account_name`：账号名称
  - `password`：账号密码（明文存储）
  - `platform_code`：平台编码（关联客户端系统的bt_platform表）
  - `device_id`：设备ID（关联设备表的device_id，一对一关系）
  - `is_auto_assign`：是否自动分配（0-否，1-是）
  - `execution_status`：执行状态（0-空闲，1-执行中）
  - `execution_start_time`：执行开始时间（用于检测超时）
  - `status`：状态（0-禁用，1-启用）
- 索引：
  - `uk_device_id`：设备ID唯一索引
  - `idx_execution_status`：执行状态索引
  - `idx_execution_start_time`：执行开始时间索引
  - `idx_execution_status_start_time`：执行状态和执行开始时间联合索引

**账号订单类型关联表（bt_review_account_order_type）**
- 支持一个账号关联多个订单类型（能力标签）
- 核心字段：
  - `review_account_id`：测评账号ID
  - `order_type_id`：订单类型ID（关联客户端系统的bt_order_type表）
  - `sort`：排序

**设备表（bt_device）**
- 存储设备信息，账号与设备是一对一关系
- 核心字段：
  - `device_id`：设备ID（设备唯一标识）
  - `device_name`：设备名称
  - `device_type`：设备类型
  - `status`：状态（0-禁用，1-启用）

#### 2.1.3 财务账单管理模块

**账单表（bt_bill）**
- 存储账单信息
- 核心字段：
  - `tenant_id`：租户ID
  - `order_batch_id`：批次订单ID（关联测评系统的bt_order_batch表）
  - `bill_scene`：账单场景
  - `budget_amount`：预算金额
  - `actual_amount`：实际金额
  - `currency`：币种（默认KRW）
  - `payment_status`：支付状态（0-未支付，1-已支付，2-部分支付，3-已退款）
  - `payment_time`：支付时间
  - `payment_method`：支付方式
  - `bill_date`：账单日期

**账单明细表（bt_bill_detail）**
- 存储账单明细信息
- 核心字段：
  - `bill_id`：账单ID
  - `item_name`：明细项名称
  - `item_type`：明细项类型
  - `quantity`：数量
  - `unit_price`：单价
  - `budget_amount`：预算金额
  - `actual_amount`：实际金额

#### 2.1.4 帮助文档管理模块

**帮助文档表（bt_help_document）**
- 存储帮助文档信息，支持目录层级结构
- 核心字段：
  - `parent_id`：父级ID（用于构建目录层级结构）
  - `is_directory`：是否是目录（0-文档，1-目录）
  - `doc_title`：文档标题/目录名称
  - `doc_content`：文档内容
  - `doc_type`：文档类型
  - `doc_category`：文档分类
  - `status`：状态（0-禁用，1-启用）
  - `view_count`：查看次数

### 2.2 客户端系统数据库设计

**产品表（bt_product）**

- 核心字段：

  - `store_id`：店铺ID

  - `platform_product_id`：平台产品ID（唯一，不可修改）

  - `attribute_name`：属性名称
  - `main_image_url`：产品主图URL
  - `status`：状态（0-禁用，1-启用）

**订单表（bt_order）**
- 存储客户填写的订单
- 核心字段：
  - **基础信息**：

    - `order_batch_id`：批次订单ID
    - `product_id`：产品ID
    - `store_id`：店铺ID
    - `order_type_id`：订单类型ID
  - **冗余字段**（保证历史数据准确性）：
    - `platform_product_id`：平台产品ID
    - `store_name_kr`：店铺韩文名称
    - `store_name_custom`：店铺自定义备注名称
    - `platform_name`：平台名称
    - `operation_scene`：操作场景（0-测评，1-点击，2-加购）
    - `first_level_type_name`：一级类型名称
    - `second_level_type_name`：二级类型名称
    - `product_title`：产品标题
    - `product_link`：产品链接
    - `attribute_name`：属性名称
    - `main_image_url`：产品主图URL
    - `selling_price`：售价
  - **订单状态**：
    - `order_status`：订单状态（0-待开始，1-待分配，2-进行中，3-待确认，4-已完成）
  - **账号分配**：
    - `account_assign_result`：账号分配结果（0-失败，1-成功）

    - `platform_order_no`：平台订单号

    - `tracking_number`：物流单号
    - `actual_order_price`：实际下单价格
    - `order_account`：下单账号
    - `device_id`：设备ID
    - `keyword`：关键词
    - `click_count`：点击数量
    - `cart_count`：加购数量
    - `planned_execution_date`：计划执行日期
    - `execution_time`：执行时间
    - `review_text_content`：评论文字内容

## 三、业务流程设计

### 3.1 订单创建流程

1. **客户填写订单**
   - 客户在测评系统选择操作场景（测评、点击、加购）
   - 填写订单信息（产品、店铺、订单类型、计划执行日期等）
   - 填写详细信息（关键词、点击数量、加购数量等）

2. **保存批次订单**
   - 保存数据到 `bt_order_batch`（状态：待提交）
   - 保存明细订单到 `bt_order`（状态：待开始）

3. **提交订单**
   - 更新批次订单状态为"待支付佣金"
   - 生成账单和账单明细（`bt_bill`、`bt_bill_detail`）

4. **支付佣金**
   - 客户线下支付佣金
   - 管理员在后台系统更新支付状态
   - 更新批次订单状态为"已支付佣金"
   - 更新该批次订单状态为"待分配"

### 3.2 订单分配流程

#### 3.2.1 自动分配流程

1. **定时任务触发**
   - 定时任务（建议每1分钟执行一次）检查待分配的订单
   - 一次获取50个待分配订单

2. **获取账号分配现状**
   - 基于订单类型分组，按照账号分配数从小到大排序
   - 优先使用未有分配订单的账号，其次是分配少的账号

3. **从Redis获取账号能力标签**
   - Key：`evaluation-system-client:ability_label`
   - HashKey：`ordertypeid`
   - Value：自动分配账号集合

4. **分配规则**
   - 规则1：自动分配账号（`is_auto_assign = 1`）
   - 规则2：分配类型匹配（账号支持该订单类型）
   - 规则3：满足前两者分配账号最少的账号

5. **获取空闲账号**
   - 获取空闲账号（`execution_status = 0`）
   - 或执行时间超过15分钟的账号（正常一个业务不需要执行这么久）

6. **更新账号状态**
   - 更新空闲账号为进行中及执行开始时间
   - 防止有其他自动化服务又获取该设备处理业务
   - 防止服务突然挂掉，通过执行时间控制执行超时

7. **分配订单**
   - 更新 `bt_order` 账号设备数据（状态：进行中）
   - 如果是点击和加购场景，直接更新订单状态为"待确认"
   - 如果是测评场景，保持"进行中"状态

#### 3.2.2 手动分配流程

1. **管理员选择订单**
   - 管理员在后台系统选择待分配的订单

2. **选择执行账号**
   - 选择可用的测评账号

3. **确认分配**
   - 更新订单状态为"进行中"
   - 更新账号状态为"执行中"
   - 记录账号分配时间和结果

### 3.3 自动化业务执行流程

#### 3.3.1 自动化任务流程

1. **定时任务触发**
   - 自动化任务（同时间同一个服务器只有一个任务在执行，避免一台机器压力太大）

2. **获取空闲账号**
   - 分页获取空闲账号（一次取10个）

3. **多线程执行**
   - 一个设备一个线程，保证有序

4. **获取待执行订单**
   - 基于每个空闲设备ID获取待确认订单且重试次数小于等于3次
   - 分页获取，一页获取50个

5. **自动化执行**
   - 支持重复执行和重试
   - 执行测评、点击、加购等业务

6. **更新执行结果**
   - 执行成功：更新订单状态和结果
   - 执行失败：记录失败状态和原因，执行重试次数+1

7. **更新账号状态**
   - 如果当前设备还有订单数据要执行：更新账号执行时间
   - 如果当前设备没有订单数据要执行：更新账号执行状态和执行时间为空闲

#### 3.3.2 点击场景特殊处理

1. **执行点击**
   - 成功点击次数+1

2. **判断是否完成**
   - 点击成功次数大于等于计划点击次数一致

3. **更新订单状态**
   - 如果完成：更新订单状态为"已完成"
   - 如果未完成：继续执行

#### 3.3.3 测评场景特殊处理

1. **人工处理**
   - 管理员可以人工处理测评订单
   - 更新订单号（测评场景）
   - 更新订单状态为"待确认"

2. **客户确认**
   - 客户确认订单完成
   - 更新订单状态为"已完成"

### 3.4 账号状态管理流程

#### 3.4.1 执行状态管理

1. **状态变更**
   - 空闲（0）→ 执行中（1）：分配订单时
   - 执行中（1）→ 空闲（0）：执行完成或超时

2. **执行开始时间记录**
   - 当账号状态变为执行中时，记录 `execution_start_time`

3. **超时检测与自动释放**
   - 定时任务（建议每1分钟执行一次）检查所有执行中的账号
   - 如果 `execution_start_time` 距离当前时间超过设定的超时时间（如30分钟），则认为执行超时
   - 自动将超时的账号状态恢复为"空闲"，清空 `execution_start_time`
   - 这样可以防止执行中状态长时间未释放，导致业务场景不能正常进行

### 3.5 账号能力标签管理流程

1. **管理员配置**
   - 管理员在后台系统配置账号的能力标签（订单类型）

2. **更新关联表**
   - 更新 `bt_review_account_order_type` 表

3. **更新Redis缓存**
   - 删除缓存，后续账号自动分配直接查缓存
   - Key：`evaluation-system-client:ability_label`
   - HashKey：`ordertypeid`
   - Value：自动分配账号集合

4. **账号删除处理**
   - 如果删除账号，同时删除能力标签
   - 更新Redis缓存

## 四、核心功能模块

### 4.1 客户功能模块

#### 4.1.1 平台管理
- 查看平台列表（coupang、naver等）

#### 4.1.2 订单类型管理
- 查看订单类型列表

#### 4.1.3 店铺管理
- 添加店铺（输入店铺韩文名称+自定义备注名称）
- 修改店铺（仅支持修改自定义备注名称，仅客户管理员账号使用）
- 删除店铺（逻辑删除，改状态即可）

#### 4.1.4 产品管理
- 自动添加：输入产品链接，爬取产品信息自动添加
- 手动添加：手动输入所有产品信息
- 修改产品：可以修改除产品ID外的所有信息
- 删除产品（逻辑删除）

#### 4.1.5 订单创建和填写
- 填写订单：支持多种填写方式
  - 某一天，单一产品的订单信息
  - 某一天，不同产品的订单信息
  - 某单一产品某几天的订单信息
  - 不同产品某几天的订单信息
- 导入订单：可以选择任意已提交的订单重新提交
- 点击/加购：
  - 某一产品，未来某短时间内的点击数量总数
  - 某几个产品，未来某短时间内的点击数量总数
  - 某一产品，未来某段时间内的加购数量总数
  - 某几个产品，未来某段时间内的加购数量总数

#### 4.1.6 订单查询
- 待开始订单：提前填写，但还未到日期开始（order_status = 0）
- 待分配订单：已到执行日期，等待分配执行账号（order_status = 1）
- 进行中订单：订单任务已经分配，正在执行中（order_status = 2）
- 待确认订单：还未上评的订单（order_status = 3）
- 已完成订单：订单已经评价完毕，订单终结（order_status = 4）

#### 4.1.7 批次订单管理
- 批次查询
- 批次取消（未开始的可以取消）

#### 4.1.8 账单查询
- 查看账单信息

#### 4.1.9 用户角色菜单权限管理
- 租户之间数据隔离

## 五、技术实现要点

### 5.1 并发控制

#### 5.1.1 账号分配并发控制
- 使用 `execution_status` 和 `execution_start_time` 字段控制并发
- 分配账号时，更新账号状态为"执行中"并记录执行开始时间
- 防止多个自动化服务同时获取同一设备

#### 5.1.2 自动分配任务并发控制
- 自动分配任务（同时间只能一个节点执行）
- 使用分布式锁或数据库锁保证同一时间只有一个节点执行

#### 5.1.3 自动化任务并发控制
- 自动化任务（同时间同一个服务器只有一个任务在执行）
- 避免一台机器压力太大

### 5.2 超时处理

#### 5.2.1 账号执行超时
- 定时任务检查执行中的账号
- 如果执行开始时间超过30分钟，自动释放账号状态
- 防止执行中状态长时间未释放

#### 5.2.2 订单执行超时
- 订单执行失败时，记录重试次数
- 重试次数小于等于3次时，可以重新执行
- 超过3次后，需要人工处理

### 5.3 缓存设计

#### 5.3.1 账号能力标签缓存
- Key：`evaluation-system-client:ability_label`
- HashKey：`ordertypeid`
- Value：自动分配账号集合
- 更新时机：账号能力标签变更时删除缓存

### 5.4 数据冗余设计

#### 5.4.1 订单表冗余字段
订单表中冗余了以下关键字段，用于保存订单创建时的快照数据：
- 店铺信息：`store_name_kr`、`store_name_custom`
- 平台信息：`platform_name`
- 订单类型信息：`operation_scene`、`first_level_type_name`、`second_level_type_name`
- 产品信息：`platform_product_id`、`product_title`、`product_link`、`attribute_name`、`main_image_url`、`selling_price`

#### 5.4.2 冗余字段的作用
- **历史数据准确性**：即使关联表的数据发生变化，订单表中的冗余字段保持不变
- **查询性能**：减少关联查询，提升查询性能
- **数据追溯**：可以准确追溯订单创建时的原始数据

### 5.5 索引设计

#### 5.5.1 索引设计原则
- 为经常用于WHERE条件的字段建立索引
- 为外键关联字段建立索引
- 为排序和分组字段建立索引
- 避免过度索引，平衡查询性能和写入性能

#### 5.5.2 关键索引
- 外键字段索引：`tenant_id`、`order_batch_id`、`product_id`、`store_id`等
- 状态字段索引：`status`、`order_status`、`batch_order_status`、`execution_status`、`payment_status`等
- 日期字段索引：`planned_execution_date`、`execution_start_time`、`bill_date`等
- 业务查询字段索引：`platform_code`、`platform_order_no`、`device_id`、`operation_scene`、`order_account`等
- 联合索引：`idx_execution_status_start_time`（执行状态和执行开始时间）

## 六、数据同步方案

### 6.1 同步策略

#### 6.1.1 实时同步
对于关键数据，采用实时同步：
- 订单创建：客户创建订单后，立即同步到后台系统
- 订单状态更新：后台系统更新订单状态后，立即同步到测评系统
- 支付状态：客户支付后，立即同步到后台系统

#### 6.1.2 定时同步
对于非关键数据，采用定时同步：
- 店铺数据：每小时同步一次
- 产品数据：每小时同步一次
- 客户信息：每天同步一次

### 6.2 同步实现方式

#### 6.2.1 消息队列（推荐）
- 使用 RabbitMQ、Kafka 等消息队列
- 数据变更时发送消息
- 消费端接收消息并同步数据

#### 6.2.2 数据库触发器
- 在数据库层面设置触发器
- 数据变更时触发同步逻辑
- 适合简单的同步场景

#### 6.2.3 接口调用
- 通过 REST API 或 RPC 调用
- 数据变更时调用同步接口
- 适合实时性要求高的场景

#### 6.2.4 共享数据库视图
- 对于只读数据，使用数据库视图
- 两个系统访问同一个视图
- 适合配置类数据

### 6.3 数据一致性保证

#### 6.3.1 主数据源
- **租户数据**：后台系统为主数据源
- **平台数据**：客户端系统为主数据源（创建和修改）
- **订单类型数据**：客户端系统为主数据源（创建和修改）
- **店铺数据**：客户端系统为主数据源（创建和修改）
- **产品数据**：客户端系统为主数据源（创建和修改）
- **订单数据**：客户端系统为主数据源（创建），后台系统为主数据源（状态更新）
- **账单数据**：后台系统为主数据源（创建和管理）

#### 6.3.2 冲突处理
1. **客户信息冲突**：以后台系统为准
2. **店铺/产品信息冲突**：以客户端系统为准（客户自己的数据）
3. **订单状态冲突**：以后台系统为准（管理员分配和状态更新）

## 七、部署方案

### 7.1 数据库部署

#### 7.1.1 方案一：同一数据库
- 两个系统使用同一个数据库，通过表前缀区分
- 优点：部署简单，数据同步方便
- 缺点：数据隔离性较差

#### 7.1.2 方案二：不同数据库
- 两个系统使用不同数据库，通过接口或消息队列同步
- 优点：数据隔离性好，便于独立扩展
- 缺点：需要实现数据同步机制

### 7.2 应用部署

#### 7.2.1 后台管理系统部署
- 部署在内部服务器
- 仅管理员和员工可以访问
- 需要配置防火墙和安全策略

#### 7.2.2 客户端系统部署
- 部署在公网服务器
- 客户可以通过互联网访问
- 需要配置HTTPS和安全认证

#### 7.2.3 自动化系统部署
- 可以部署在独立的服务器
- 需要与后台系统网络互通
- 建议使用容器化部署，便于扩展

### 7.3 监控和运维

#### 7.3.1 监控指标
- 系统性能监控（CPU、内存、磁盘、网络）
- 数据库性能监控（连接数、慢查询、锁等待）
- 业务指标监控（订单数量、分配成功率、执行成功率）
- 错误日志监控

#### 7.3.2 运维建议
- 定期备份数据库
- 监控数据同步状态
- 定期校验数据一致性
- 建立数据同步异常处理机制
- 定期清理过期数据（如操作历史记录保留1年）

### 12.3 关键SQL示例

#### 查询待分配订单
```sql
SELECT * FROM bt_order 
WHERE order_status = 1 
  AND planned_execution_date <= CURDATE()
ORDER BY create_time ASC
LIMIT 50;
```

#### 查询空闲账号
```sql
SELECT * FROM bt_review_account 
WHERE execution_status = 0 
  AND is_auto_assign = 1 
  AND status = 1
  AND platform_code = ?
ORDER BY id ASC
LIMIT 10;
```

#### 查询超时的执行中账号
```sql
SELECT * FROM bt_review_account 
WHERE execution_status = 1 
  AND execution_start_time < DATE_SUB(NOW(), INTERVAL 30 MINUTE);
```

#### 更新超时账号状态
```sql
UPDATE bt_review_account 
SET execution_status = 0, execution_start_time = NULL 
WHERE execution_status = 1 
  AND execution_start_time < DATE_SUB(NOW(), INTERVAL 30 MINUTE);
```
